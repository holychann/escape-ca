# 이야기 서버 배포 (AWS Lightsail 인스턴스)

이야기 서버를 Lightsail 인스턴스 한 대에 Docker로 띄웁니다. 서버 이미지는 `server/Dockerfile` 그대로 쓰고, 앞에 Caddy를 두어 HTTPS 인증서를 자동으로 받습니다.

```
차 앱 ──HTTPS──▶ Caddy (80, 443) ──▶ story (8787, 바깥에 열지 않음) ──▶ Gemini / Claude
                                        └ /app/data 볼륨: episodes.jsonl, reports.jsonl, daily_limit.json, 그림
```

| 파일 | 하는 일 |
|---|---|
| `Dockerfile`, `.dockerignore` | 서버 이미지 (클라우드 배포용으로 이미 있던 것 그대로) |
| `compose.yaml` | 서버와 Caddy를 함께 띄우고, 기록과 인증서를 볼륨에 둡니다. 서버의 8787은 바깥에 열지 않습니다 |
| `Caddyfile` | HTTPS, HTTP→HTTPS 넘기기, 요청 본문 64KB 제한, 응답 대기 6분 |

## 1. 인스턴스 만들기 (Lightsail 콘솔)

1. **인스턴스 생성**: 리전 **서울(ap-northeast-2)**, 플랫폼 **Linux/Unix**, 청사진 **OS 전용 → Ubuntu 24.04 LTS**
2. **요금제**: 메모리 **1GB 이상**. 그림 여러 장을 한꺼번에 다루면 512MB는 빠듯합니다. 요금은 콘솔에서 확인하세요.
3. **고정 IP**: 네트워킹 탭에서 고정 IP를 만들어 이 인스턴스에 붙입니다. 붙이지 않으면 재시작할 때 IP가 바뀌어 인증서와 앱 주소가 깨집니다.
4. **방화벽**(인스턴스 → 네트워킹 → IPv4 방화벽): **HTTPS(TCP 443)** 를 추가합니다. SSH(22)와 HTTP(80)는 기본으로 열려 있습니다. 80은 인증서 발급에 쓰니 닫지 마세요.

## 2. 주소 정하기

인증서는 IP가 아니라 이름에 발급되므로 주소가 하나 필요합니다.

- **도메인이 있으면**: DNS에 A 레코드(예: `story.example.com`)로 고정 IP를 넣습니다.
- **도메인이 없으면**: IP의 점을 줄표로 바꾼 `13-125-1-2.sslip.io` 같은 주소를 씁니다. 따로 등록할 필요가 없습니다. 다만 남의 서비스에 기대는 것이라, 오래 쓸 거면 도메인을 권합니다.

## 3. 서버에 Docker 설치

콘솔의 **SSH를 사용하여 연결**(브라우저 터미널)로 들어가서:

```bash
sudo apt-get update
```

```bash
sudo apt-get install -y docker.io docker-compose-v2 git
```

```bash
sudo usermod -aG docker ubuntu
```

`usermod` 뒤에는 SSH 창을 닫았다가 다시 열어야 `sudo` 없이 `docker`를 쓸 수 있습니다.

## 4. 코드 받기와 .env

서버에는 `server/` 폴더만 있으면 됩니다. 차 앱 코드, APK, 앱 그림은 받지 않도록 필요한 폴더만 받습니다.

```bash
git clone --filter=blob:none --sparse https://github.com/leekwangeun/escape-car.git
```

```bash
cd escape-car && git sparse-checkout set server && cd ..
```

`ls escape-car`를 했을 때 `server`와 루트 문서 몇 개만 보이면 됩니다. 나중에 `git pull`을 해도 `server/`만 받습니다.

```bash
cd escape-car/server && cp .env.example .env && chmod 600 .env && nano .env
```

`.env`에 채울 것:

- 키 세 개. 각자 맡은 일이 다릅니다.
  - `ANTHROPIC_API_KEY`: Claude로 이야기 글을 씁니다. 글 모델 기본값이 Claude(`STORY_PROVIDER=claude`)라서 이 키가 없으면 앱이 기본 이야기로 진행합니다.
  - `GEMINI_API_KEY`: 무료 Gemini 키. 무료 한도 안에서 루미 대사를 읽어 줍니다(TTS).
  - `GEMINI_API_KEY_PAID`: 유료 Gemini 키. 그림은 이 키로만 그립니다. 무료 키가 한도를 넘거나 실패하면 대사도 이 키로 읽습니다. 비워 두면 AI 그림이 없고, 그런 대사는 자막으로만 나옵니다.
- 루미 목소리: `.env.example`에 있는 `TTS_VOICE`와 `TTS_STYLE` 두 줄은 그대로 둡니다. 지우면 코드 기본 목소리(`Leda`)로 읽습니다.
- 이야기 창고를 쓰려면 아래 **이야기 창고 (S3)** 의 `STORY_LIBRARY_*`
- `STORY_DOMAIN=` 2번에서 정한 주소 (예: `STORY_DOMAIN=13-125-1-2.sslip.io`). 줄 맨 앞에 `#` 없이 씁니다.

`STORY_TRUST_PROXY`와 `STORY_DATA_DIR`은 `compose.yaml`이 정해 주므로 적지 않아도 됩니다. `.env`는 서버에서만 만들고, 저장소나 메시지에 붙이지 않습니다.

## 5. 띄우기

```bash
docker compose up -d --build
```

처음에는 이미지를 만들고 인증서를 받느라 1~2분 걸립니다. 확인:

```bash
docker compose ps
```

```bash
curl https://13-125-1-2.sslip.io/health
```

`{"ok":true,"pictures":true,"voice":true}`가 나오면 됩니다. `GEMINI_API_KEY_PAID`가 없거나 `IMAGE_MODEL=off`면 `pictures`가 `false`이고, Gemini 키가 둘 다 없거나 `TTS_MODEL=off`면 `voice`가 `false`입니다. 인증서를 못 받으면 `docker compose logs caddy`를 보세요. 대개 방화벽 80/443이 닫혀 있거나 주소가 고정 IP를 가리키지 않아서입니다.

## 6. 앱을 배포 서버에 붙이기

PC에서 배포 주소로 APK를 다시 빌드합니다. 주소가 `https://`면 앱의 평문 HTTP 허용은 자동으로 꺼집니다.

```bash
cd car && ./gradlew assembleRelease -PstoryUrl=https://13-125-1-2.sslip.io
```

이때는 `adb reverse`가 필요 없습니다.

## 7. 자동 배포

팀 저장소(`leekwangeun/escape-car`) `main`에 커밋이 들어오면(PR merge, 직접 push 모두) 테스트를 통과한 것만 서버에 저절로 적용됩니다. **GitHub에 넣는 비밀 값(키, 비밀번호)은 없습니다.** GitHub가 서버에 들어오는 대신, 서버가 2분마다 GitHub를 보고 스스로 배포합니다.

```
main에 merge ─▶ GitHub Actions '서버 테스트'(pytest)
                         ▲
Lightsail 서버 (2분마다) ─┴─ main 맨 끝 커밋의 테스트 결과를 봄(공개 저장소라 키 없이 읽음)
   통과 ─▶ deploy/lightsail_deploy.sh: git fast-forward → docker compose up -d --build → healthy까지 기다림
   실패 ─▶ 배포하지 않음. 다시 돌려 통과하면 그때 배포
```

merge부터 서버에 반영되기까지 테스트 1~2분과 확인 간격 2분, 이미지 빌드 시간을 더해 보통 5분 안팎입니다.

| 파일 | 하는 일 |
|---|---|
| `.github/workflows/server-tests.yml` | main에 들어온 커밋과 main으로 가는 PR마다 서버 테스트. 서버는 job 이름 `server-tests`로 결과를 찾습니다 |
| `server/deploy/lightsail_poll.sh` | 서버가 2분마다 돌림. 새 커밋이 있고 테스트가 통과했으면 배포 스크립트를 부름 |
| `server/deploy/lightsail_deploy.sh` | 실제 배포. 그 커밋까지 fast-forward로 받고 다시 빌드해 띄움. 손으로 돌려도 됨 |
| `server/deploy/escape-deploy.service`, `escape-deploy.timer` | 2분마다 `lightsail_poll.sh`를 돌리는 systemd 설정 |

코드가 그대로인 커밋(`car/`만 바뀐 PR 등)도 같은 순서로 지나가지만, 이미지가 캐시에서 나와 서버는 다시 시작하지 않습니다.

### 처음 한 번 할 설정

서버의 브라우저 SSH에서 합니다. 저장소가 `/home/ubuntu/escape-car`에 있다고 보고 만든 설정입니다(4번 절 그대로 받았으면 맞습니다).

1. **코드 받기**: 이 설정이 들어간 main을 받습니다.

   ```bash
   cd ~/escape-car && git pull
   ```

2. **타이머 설치**:

   ```bash
   sudo cp ~/escape-car/server/deploy/escape-deploy.service ~/escape-car/server/deploy/escape-deploy.timer /etc/systemd/system/
   ```

   ```bash
   sudo systemctl daemon-reload && sudo systemctl enable --now escape-deploy.timer
   ```

3. **확인**: 2분쯤 뒤 기록을 봅니다. 처음에는 지금 main을 한 번 배포합니다.

   ```bash
   journalctl -u escape-deploy --since "10 min ago" --no-pager
   ```

   `deploy: 끝`이 보이면 됩니다. 다음 확인 시각은 `systemctl list-timers escape-deploy.timer`로 봅니다.

### 알아 둘 것

- **배포하는 동안 잠깐 끊깁니다**: 새 이미지를 다 만든 뒤 컨테이너를 바꿔 끼우는 동안(창고를 읽는 시간 포함 최대 1분쯤) 이야기 요청이 실패할 수 있습니다. 앱은 그때 기본 이야기로 진행합니다.
- **배포 결과는 서버 기록에 남습니다**: GitHub Actions에는 테스트 결과만 나옵니다. 서버에 반영됐는지는 `journalctl -u escape-deploy`로 봅니다. 할 일이 없을 때는 기록을 남기지 않습니다.
- **배포가 실패한 커밋은 다시 시도하지 않습니다**: 망가진 빌드를 2분마다 되풀이하지 않게, 다음 커밋이 올 때까지 기다립니다. 서버에서 원인을 고친 뒤(예: `.env`) 바로 다시 하려면 `bash ~/escape-car/server/deploy/lightsail_deploy.sh`를 돌립니다.
- **되돌리기**: 문제가 있는 PR은 GitHub에서 Revert PR을 만들어 merge하면 그 상태로 다시 배포됩니다.
- **`.env`는 자동 배포 대상이 아닙니다**: 키나 설정을 바꿀 때는 지금처럼 서버에서 `.env`를 고치고 `docker compose up -d`를 합니다. 새 코드가 새 설정을 요구하면, merge 전에 서버 `.env`부터 고쳐 둡니다.
- **서버에서 코드를 직접 고치지 마세요**: 서버 저장소에 손으로 고친 파일이 있으면 배포가 `git merge --ff-only`에서 멈춥니다. 서버에서 `git status`로 무엇이 바뀌었는지 보고 `git restore`로 되돌립니다.
- **테스트를 건너뛴 커밋은 배포되지 않습니다**: 커밋 메시지에 `[skip ci]`를 넣으면 테스트 결과가 없어 서버가 계속 기다립니다. 그럴 때는 Actions에서 '서버 테스트'를 손으로 돌리거나 배포 스크립트를 손으로 돌립니다.
- **잠시 끄기**: `sudo systemctl stop escape-deploy.timer`, 다시 켜기: `sudo systemctl start escape-deploy.timer`.
- **타이머 설정 파일을 바꾸면**: `escape-deploy.service`나 `.timer`가 바뀐 커밋이 배포되면 2번을 다시 해야 적용됩니다(스크립트 두 개는 저절로 새 것으로 돕니다).
- **GitHub API 요청 한도**: 서버는 새 커밋을 기다리는 동안에만 GitHub API를 부릅니다(2분마다 한 번, 키 없는 요청 한도는 시간당 60번).

## 이야기 창고 (S3)

검사를 통과한 Claude 이야기를 S3 버킷에 쌓아 다른 차가 다시 쓰게 합니다(동작은 `README.md`의 '이야기 창고'). 켜지 않으면 지금과 똑같이 동작합니다.

1. **버킷**: 이야기 창고 전용 버킷을 하나 만들고 **퍼블릭 액세스는 모두 막습니다**. 서울(ap-northeast-2)이면 서버와 가깝습니다. 글만 쌓으므로 크기는 작습니다.
2. **버킷 전용 키**: 그 버킷 하나에만 `s3:GetObject`, `s3:PutObject`, `s3:ListBucket`을 허용하는 IAM 사용자를 만들고, 그 사용자의 액세스 키를 씁니다. 다른 서비스나 다른 버킷을 건드릴 수 있는 키는 쓰지 않습니다. 키는 서버 `.env`에만 적고 저장소, 메시지, 문서에 붙이지 않습니다.
3. **`.env`**:
   - `STORY_LIBRARY_BUCKET=` 버킷 이름
   - `STORY_LIBRARY_PREFIX=` 버킷 안의 폴더(비워도 됩니다)
   - `AWS_DEFAULT_REGION=` 버킷의 리전, `AWS_ACCESS_KEY_ID=`와 `AWS_SECRET_ACCESS_KEY=` 2번의 키 (boto3 표준 환경 변수)
   - 나머지(`STORY_LIBRARY_MODELS`, `STORY_LIBRARY_CAP` 등)는 `.env.example`의 기본값으로 충분합니다. 기본으로 Claude가 쓴 이야기만 쌓습니다.
4. 다시 띄우면(`docker compose up -d --build`) 서버가 창고를 읽어 다시 검사합니다. 로그에 `shelf:`로 시작하는 줄이 건너뛴 이야기를 알려 줍니다. 창고를 못 읽으면 서버는 창고 없이 뜹니다.
5. 창고의 이야기는 설치 ID, IP, 소원, 계절, 시간대 없이 글만 있습니다. 문제가 있는 이야기를 빼려면 신고가 오거나, 버킷의 `blocked/{storyId}.json`에 파일을 하나 넣으면 됩니다(`{"reason": "..."}`). 손으로 넣은 파일은 **서버를 다시 띄운 뒤에야** 적용됩니다(신고로 생긴 표시는 바로 적용됩니다).
6. 창고는 **`STORY_PROVIDER=claude`와 함께** 켭니다. 글 모델이 Gemini이면 소원 없는 이야기도 계절 없이 쓰지만 창고에는 하나도 쌓이지 않습니다.
7. 창고가 커질수록 서버가 다시 뜨는 데 걸리는 시간이 늡니다. 읽기는 `STORY_LIBRARY_LOAD_SECONDS`(기본 60초)까지만 기다리고, 넘기면 그때까지 읽은 이야기로 뜹니다(나머지는 다음에 다시 뜰 때 읽습니다).

## 운영

| 할 일 | 명령 (`escape-car/server`에서) |
|---|---|
| 코드 바꾼 뒤 다시 배포 | main에 merge되면 자동(7번). 손으로 할 때: `bash deploy/lightsail_deploy.sh` |
| 자동 배포 기록 | `journalctl -u escape-deploy -n 50 --no-pager` |
| 서버 로그 | `docker compose logs -f story` |
| 부모 신고 보기 | `docker compose exec story cat /app/data/reports.jsonl` |
| 기록 백업 | `docker compose cp story:/app/data ./backup-$(date +%F)` |
| 재시작 / 멈춤 | `docker compose restart` / `docker compose down` |

- **볼륨을 지우지 마세요**: `docker compose down -v`는 기록, 신고, 하루 생성 횟수, 인증서를 모두 지웁니다. 인증서를 너무 자주 다시 받으면 Let's Encrypt 발급 횟수 제한에 걸립니다.
- **프로세스는 하나만**: 하루 생성 제한(설치당 20편, 주소당 200편, 서버 전체 300편)은 `daily_limit.json`에 남아 재시작해도 이어서 셉니다. 다만 프로세스 하나가 혼자 쓴다고 보고 만든 것이라, uvicorn `--workers`를 늘리거나 서버를 여러 대 띄우지 마세요.
- **8787을 바깥에 열지 마세요**: 서버는 `X-Forwarded-For`의 첫 주소로 주소별 제한을 셉니다(`STORY_TRUST_PROXY=1`). Caddy는 차가 보낸 `X-Forwarded-For`를 버리고 실제 주소로 바꾸지만, 8787이 열려 있으면 누구나 이 헤더를 꾸며 제한을 피할 수 있습니다.
- **소원 이야기의 그림은 24시간 뒤 지워집니다**(`STORY_IMAGE_TTL_HOURS`). 앱은 이야기를 받을 때 그림도 받아 기기에 저장하므로 문제없습니다. 이야기 창고의 이야기에는 그림이 없어 이 정리와 상관없습니다.
- **접속 기록**: Caddy는 접속 기록을 남기지 않게 해 두었습니다. 서버(uvicorn)의 접속 기록에는 IP 주소가 찍히니, `docker compose logs`를 남에게 보낼 때는 조심하세요.
- **비용**: 실제 모델을 부르는 건 `/v1/episode`뿐입니다. 공개 주소라 누구나 부를 수 있으니, `.env`의 `STORY_DAILY_TOTAL` 등으로 하루 한도를 조정하고 Gemini/Anthropic 콘솔에도 월 사용 한도를 걸어 두세요.
- **출시 전**: Gemini API는 18세 미만 대상 서비스에 쓸 수 없습니다(`README.md`의 '모델과 정책'). 공모전 시연이 끝나고 실제로 공개하려면 작성 모델부터 바꿔야 합니다.
